# PrettyCode website

A small, static [Quarto](https://quarto.org/) showcase for [prettycode-agent](https://github.com/ealvaradomena/prettycode-agent). The website and application live in separate repositories. Nothing here runs a model, needs an API key, or executes the example code.

## Files

- `index.qmd` — the entire single-page website
- `styles.css` — its visual styling
- `_quarto.yml` — site configuration
- `prettycode-site.Rproj` — open the project in RStudio
- `.github/workflows/publish.yml` — automatic GitHub Pages deployment

## Preview locally

Install [Quarto](https://quarto.org/docs/get-started/) if needed. Open `prettycode-site.Rproj` in RStudio, or open a terminal in this folder, then run:

```bash
quarto preview
```

To generate the static website once:

```bash
quarto render
```

Rendered files appear in the ignored `_site/` directory.

## Publish on GitHub Pages

1. Create a public **empty** GitHub repository named `prettycode-site` (separate from `prettycode-agent`), and push this directory's files to its `main` branch. The included GitHub Action automatically builds and publishes to `gh-pages` on pushes to `main`.
2. In the GitHub repository, open **Settings → Actions → General → Workflow permissions** and allow **Read and write permissions** if the workflow cannot publish with its provided `GITHUB_TOKEN`.
3. Under **Settings → Pages**, choose **Deploy from a branch**, branch **`gh-pages`**, folder **`/(root)`**, then Save. If `gh-pages` does not appear yet, wait until the first workflow succeeds.
4. The expected website address is `https://ealvaradomena.github.io/prettycode-site/`.

To check deployment, open the **Actions** tab; no local site build needs to be committed. `site-url` in `_quarto.yml` assumes the repo's public name and account above; change it if you publish elsewhere.

The website's Iris `Before` scripts live in `demo-inputs/iris.py` and `demo-inputs/iris.R`. Both `After` panels preserve the exact proposals generated by PrettyCode's standalone CLI using `gpt-5-mini`; the original source files were not overwritten. Python passed syntax and executable-token checks; R passed syntax checks. Neither check proves behavioral equivalence. The older `demo-inputs/example.py` and `demo-inputs/example.R` remain as historical examples. The MCP section summarizes a separate, completed Codex–PrettyCode experiment using a temporary copy of the older two-line Python example, **not the Iris script**.

## Before publishing

Run `git status --short --untracked-files=all` to review exactly what would enter the repository. The `.gitignore` excludes local render output (`_site/`), Quarto/RStudio state, generated `Rplots.pdf`, PatchMyMess backups (`old/`), and private CLI proposal files (`.prettycode-proposals/`). These files can stay locally; they are not needed for publication. If any were previously committed, ignoring them does not remove them from Git, so inspect `git ls-files old/ Rplots.pdf _site/ .prettycode-proposals/` before pushing. Keep the four `demo-inputs/` scripts because they document the two current examples and the earlier MCP test.

Then run `quarto render` and inspect `_site/index.html` (or use `quarto preview`). A successful local render and a successful GitHub Actions deployment are separate checks; confirm both before considering publication finished.

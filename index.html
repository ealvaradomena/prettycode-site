The Python example loads the Iris dataset, summarizes petal and sepal lengths by species, draws a scatter plot, and fits a linear regression. The after panel is the exact saved PrettyCode CLI proposal for demo-inputs/iris.py, generated with gpt-5-mini.

# Project Setup

# Purpose

#   species, petal length, and sepal length, display group means,
#   plot petal vs sepal length by species, and fit a simple linear
#   regression predicting sepal length from petal length
#
# Requirements
# - scikit-learn
# - matplotlib
#
# AI Disclosure

# - Editing guidance: PrettyCode Python protocol

# 1. Imports ----
from sklearn.datasets import load_iris
from sklearn.linear_model import LinearRegression
import matplotlib.pyplot as plt

# 2. Load and prepare data ----

# Load the iris dataset as a pandas DataFrame (scikit-learn provides as_frame)
iris = load_iris(as_frame=True)

# Rename lengthy column names to shorter, snake_case names for clarity
data = iris.frame.rename(
    columns={
        "petal length (cm)": "petal_length",
        "sepal length (cm)": "sepal_length",
    }
)

# Map numeric target codes to human-readable species names
# - iris.target_names contains the species labels in order
data["species"] = data["target"].map(dict(enumerate(iris.target_names)))

# Keep only the columns we need for analysis and drop any missing rows
data = data[["species", "petal_length", "sepal_length"]].dropna()

# 3. Summary statistics ----

# Print mean petal and sepal lengths for each species (rounded to 2 decimals)
print(data.groupby("species")[["petal_length", "sepal_length"]].mean().round(2))

# 4. Visualization ----

# Scatter plot of petal length vs sepal length, colored by species
for species, group in data.groupby("species"):
    plt.scatter(group["petal_length"], group["sepal_length"], label=species)

# Label axes, show legend, and display the figure
plt.xlabel("Petal length (cm)")
plt.ylabel("Sepal length (cm)")
plt.legend()
plt.show()

# 5. Simple linear regression ----

# Fit a linear model predicting sepal length from petal length
model = LinearRegression().fit(data[["petal_length"]], data["sepal_length"])

# Print model parameters (intercept and slope)
print("Intercept:", model.intercept_, "Slope:", model.coef_[0])

R

The R example summarizes the built-in Iris data by species, visualizes petal and sepal lengths with ggplot2, and fits a linear model. The after panel is the exact saved PrettyCode CLI proposal for demo-inputs/iris.R, generated with gpt-5-mini.

Before

library(ggplot2)

data <- na.omit(iris[c("Species", "Petal.Length", "Sepal.Length")])
print(aggregate(cbind(Petal.Length, Sepal.Length) ~ Species, data = data, FUN = mean))

plot <- ggplot(data, aes(Petal.Length, Sepal.Length, color = Species)) +
  geom_point() +
  labs(x = "Petal length (cm)", y = "Sepal length (cm)") +
  theme_minimal()
print(plot)

model <- lm(Sepal.Length ~ Petal.Length, data = data)
print(coef(model))

# - The base R 'iris' dataset is used (no external files required)

library(ggplot2)

# ////////////////////////////////////////////////////
#
#
# 1. Prepare Data ----
#
#
# ////////////////////////////////////////////////////

# Load a subset of the iris dataset and drop any rows with missing values
data <- na.omit(
  iris[c("Species", "Petal.Length", "Sepal.Length")]
)

# ////////////////////////////////////////////////////
#
#
# 2. Summary Aggregation ----
#
#
# ////////////////////////////////////////////////////

# Compute and print mean Petal.Length and Sepal.Length by Species
# Aggregation uses the base stats::aggregate behavior
print(
  aggregate(
    cbind(Petal.Length, Sepal.Length) ~ Species,
    data = data,
    FUN = mean
  )
)

# ////////////////////////////////////////////////////
#
#
# 3. Visualization ----
#
#
# ////////////////////////////////////////////////////

# Create a scatter plot of Petal.Length vs Sepal.Length colored by Species
plot <- ggplot2::ggplot(
  data,
  ggplot2::aes(Petal.Length, Sepal.Length, color = Species)
) +
  ggplot2::geom_point() +
  ggplot2::labs(
    x = "Petal length (cm)",
    y = "Sepal length (cm)"
  ) +
  ggplot2::theme_minimal()

# Print the ggplot object so it renders in interactive sessions
print(plot)

# ////////////////////////////////////////////////////
#
#
# 4. Modeling ----
#
#
# ////////////////////////////////////////////////////

# Fit a simple linear model predicting Sepal.Length from Petal.Length
model <- lm(Sepal.Length ~ Petal.Length, data = data)

# Print the model coefficients (intercept and slope)
print(coef(model))

Three interfaces

Choose the interface that fits how you work. All three belong to the same PrettyCode application; they are not three separate products.

01 · Codex Skill

Instructions and R/Python editing protocols that Codex can follow in any project. The Skill works on its own without the CLI or MCP.

Install the Skill

02 · Standalone CLI

A terminal interface for discovering files, checking syntax, and requesting model-generated proposals. AI-assisted polishing uses the OpenAI API and may incur a charge.

Use the CLI

03 · MCP server

Five local tools let compatible AI clients list, read, validate, inspect, and apply code changes. The client supplies the AI; the server makes no model requests.

Configure MCP

Using them together: The Skill tells Codex how to edit; MCP gives it tools for inspecting and applying edits. Codex can use both, but neither requires the other.

Preview, validate, decide

1. Inspect — Read the existing code and propose readability-focused edits.

2. Validate — Python changes pass parsing and an executable-token guard; R changes pass parsing. Neither check executes the user’s scripts.

3. Review — Inspect the diff. CLI proposals preview by default; MCP separates proposal inspection from application.

Important limitation: Valid syntax and unchanged Python executable tokens are safeguards, not proof that behavior is identical. Review proposed edits, especially for R, before applying them.
